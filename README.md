# tasktracker

Багтрекер команды **демонстрационной команды** в виде Telegram-бота + Mini App. Один Go-бинарь:
бот (long-polling) и веб-сервер мини-приложения в одном процессе, общий SQLite.

## Зачем
Аналитик и разработчик фиксируют баги, найденные при анализе прода, и ведут их
по конвейеру **Аналитика → Разработка**:

```
[Создание бага] → очередь Аналитика
   аналитик: причина + пути решения + скрины → «Выполнено»
        ↓ (заметки передаются)
[очередь Разработка]
   разработчик: чинит → «Выполнено» → задача закрыта
```

Общая доска «Задачи» показывает всё, что в работе; задача уходит с неё, когда
оба этапа закрыты (`analyst_done && dev_done`).

## Классификация
- Категория: **frontend** / **backend** / **server**
- Для backend — подтип: **parsing** / **matching** / **trading**

## Использование (бот)
- `/start` → выбор роли (Аналитик / Разработчик)
- `➕ Добавить баг` — заголовок → описание → категория → (подтип) → скриншоты
- `📥 Принять задачу` — следующая задача из вашей очереди
- `✅ Отметить выполненной` — выбрать задачу из списка и закрыть
- `🌐 Открыть задачник` — Mini App

И бот, и Mini App пишут в одну базу — состояние синхронно.

## Архитектура
```
cmd/tasktracker        точка входа (флаги/env, wiring)
internal/model         доменные типы
internal/store         SQLite (modernc.org/sqlite), схема в schema.sql
internal/tunnel        управление cloudflared quick tunnel, парс URL
internal/bot           Telegram bot: клиент API, FSM, очереди
internal/web           HTTP: /api/* + статика мини-аппа (go:embed), initData-auth
```

## Запуск локально (без Telegram, dev-режим)
```bash
go run ./cmd/tasktracker -dev -tunnel=false -db /tmp/tasks.db
# открыть http://127.0.0.1:8099 — auth обходится, роль = аналитик
```

## Запуск с ботом
```bash
BOT_TOKEN=... go run ./cmd/tasktracker
```
